# כיסוי מלא לפי תפקיד

הרחבה של מערכת ה-QA הקיימת מסריקת שישה תרחישי ליבה אל **מלאי כיסוי** לפי מסך, אזור, בקרה, פעולה, מצב ותפקיד.

היא **אינה מחליפה** דבר. `qa:setup` עדיין מקים את הסביבה ואת ה-fixtures, `qa:deterministic` נשאר שער החובה, ו-`qa:full` לא נגע. ההרחבה מוסיפה רוחב מעל אותו state בדיוק.

## מה זה עונה

לכל תפקיד, לכל מסלול, לכל בקרה: מה נגיש, מה חסום נכון, מה מוצג, מה ניתן להפעלה, מה נשבר, מה נעלם, ומה **לא נבדק ולמה**.

## הפעלה

```powershell
npm.cmd run qa:setup          # חייב לרוץ קודם — יוצר משתמשים, seed, fixtures ו-auth state
npm.cmd run qa:coverage       # ההילוך המלא: 6 תפקידים, סדרתית
```

לבנייה מחדש של המלאי בלבד, בלי דפדפן ובלי מסד נתונים:

```powershell
npm.cmd run qa:coverage-manifest
```

`qa:coverage` נועל את אותו mutex כמו שאר מערכת ה-QA, מאמת שהיעד הוא `supplyflow-p0` המקומי, **ואינו מבצע reset**. אין להריץ אותו במקביל ל-`npm run quality`, ל-`qa:setup` או ל-`qa:full`.

## הארכיטקטורה

| קובץ | תפקיד |
|---|---|
| `types.ts` | סכימות zod לכל תוצר. הן מקור האמת; הטיפוסים נגזרים מהן. |
| `extract.ts` | ניתוח סטטי של `src/App.tsx` ו-`src/components/Layout.tsx` עם ה-AST של TypeScript: מסלולים, guards, ‏NAV, בקרות, קריאות backend. |
| `route-metadata.ts` | מה שפרסר אינו יכול לדעת — מטרת המסך וסוגו, ומהם נגזרים המצבים הישימים. נכתב ידנית ונבדק. |
| `build-manifest.ts` | מרכיב את `application-manifest.json`. |
| `build-matrices.ts` | מרכיב את `role-route-matrix.json` ואת בסיס `role-action-matrix.json`. |
| `runtime.ts` | חצי הריצה: סריקת DOM, גלישה, יעדי מגע, סמנטיקה, דיאלוגים ובדיקת שרת. |
| `specs/coverage-walk.spec.ts` | בדיקה אחת לכל מסלול לכל תפקיד. |
| `specs/coverage-session.spec.ts` | מה שאינו שייך למסך יחיד: איבוד סשן, כשל רשת, ניווט והיסטוריה. |
| `record-store.ts` | קובץ תוצאה אחד לכל (תפקיד, מסלול). |
| `aggregate.ts` | הופך רשומות למספרים, עם הגדרה מפורשת לכל אחוז. |
| `triage.ts` | סיווג תצפיות לפי כללים בעלי שם. |
| `report.ts` | ‏JSON, ‏Markdown בעברית ו-HTML עצמאי ב-RTL. |

## מה ההילוך עושה — ומה בכוונה לא

**עושה:** ניווט לכל מסלול (מותר וחסום), סריקת כל בקרה אינטראקטיבית והצלבתה מול המניפסט, חיפוש וסינון, פתיחת דיאלוג ו-Escape, רענון ובדיקת יציבות, ‏Axe, ‏סמנטיקה (סדר כותרות, ‏th, שדות ללא שם), מקלדת, שלושה viewports, יעדי מגע, ‏console ו-network, ובדיקת שרת עם הטוקן של התפקיד עצמו למסלול חסום.

**לא עושה, בכוונה:** אינו יוצר, מאשר, משלם, מוחק או מייבא. פעולות אלה שייכות ל-`qa/deterministic/critical-workflows.spec.ts`, שם הן רצות עם verifiers עצמאיים; חזרה עליהן כאן הייתה משנה את אותם fixtures שהסוויטה ההיא נשענת עליהם. בקרה כספית או הרסנית נרשמת כ**אותרה ולא הופעלה** — זה כיסוי מלאי, לא כיסוי ביצוע, וכך היא מדווחת.

## הפרדת שני הסטטוסים

| שדה | ערכים | משמעות |
|---|---|---|
| `coverageStatus` | `COVERAGE_COMPLETED`, `COVERAGE_PARTIAL`, `COVERAGE_BLOCKED`, `INFRASTRUCTURE_FAILED` | האם בדקנו את מה שהתחייבנו לבדוק. |
| `productQualityStatus` | `PASS`, `PASS_WITH_FINDINGS`, `FAIL`, `NOT_ASSESSED` | מה מצאנו. |

תפקיד יכול להגיע ל-`COVERAGE_COMPLETED` וגם ל-`FAIL`. זה לא סותר: הראשון על הבדיקה, השני על המוצר.

## אחוזי הכיסוי

אין אחוז אחד כולל. יש אחת-עשרה קטגוריות, ולכל אחת הגדרה שמודפסת ליד המספר בדוח. שתי החלטות שחשוב להכיר:

- **מכנה אפס מחזיר 0, לא 100.** קבוצה ריקה אינה כיסוי מלא.
- **אחוז המצבים נמדד ב-`OBSERVED` בלבד.** מצב שסווג `NOT_OBSERVED` מפורט בשמו ואינו נספר, גם אם הסיווג עצמו מפורש.

## תוצרים

תחת `qa/coverage/`:

`application-manifest.json` · `role-route-matrix.json` · `role-action-matrix.json` · `component-coverage.json` · `state-coverage.json` · `coverage-summary.json` · `triage-results.json` · `coverage-gaps.he.md` · `full-coverage-report.he.md` · `full-coverage-report.html` · ושישה דוחות `<role>-full-coverage.he.md`.

ראיות גולמיות (צילומים, ‏Axe, ‏console, ‏network, ‏traces) נשארות תחת `.qa-runs/<runId>/` ויש להתייחס אליהן כאל חומר פנימי.

## שינויים בקוד המוצר

**אין.** לא נוספו `data-testid`, ‏hooks או מזהי נגישות. ההילוך מאתר בקרות לפי תפקיד סמנטי ושם נגיש בלבד — וכשבקרה חסרה שם נגיש, זה נרשם כממצא ולא נעקף בבורג. אם בעתיד יידרש מזהה בדיקה, יש לתעד אותו כאן בשמו ובסיבתו.

## מגבלות

- הענף נבנה על `codex/qa-multi-agent`, שהוא **43 קומיטים מאחורי `main`**. המלאי מתאר את האפליקציה בענף הזה — בלי `DataTable` של react-table, בלי רשימות צד-שרת, בלי `ReauthModal`/step-up ובלי org scope ו-feature flags שקיימים ב-main.
- המניפסט הסטטי הוא **השערה**. בקרה מאחורי ענף תלוי-נתונים, בדיקת תפקיד או דיאלוג סגור אינה ניתנת להבחנה סטטית מבקרה שתמיד מרונדרת. רק שלב הריצה מכריע, וכל רשומה נושאת את מקור הגילוי שלה.
- ‏`actionType`, ‏`destructive` ו-`financial` נגזרים מהתווית העברית. תווית שלא תואמת את הדפוסים תסווג שמרנית.
- סריקה מוגבלת ל-400 בקרות למסך; חריגה מסומנת במפורש.
- ‏Axe מכסה כללים אוטומטיים בלבד. נדרשת בדיקת קורא-מסך אנושית בעברית ו-RTL.
- הנתונים סינתטיים וקטנים. אין כאן מבחן עומס או נפח.

## הוספת מסלול חדש

1. הוסף אותו ל-`src/App.tsx` כרגיל — המניפסט קורא משם ולא מרשימה ידנית.
2. הוסף רשומה ל-`ROUTE_METADATA` ב-`route-metadata.ts` (מטרה + סוג). מסלול בלי רשומה נכשל בבדיקה `coverage.test.ts` במקום לקבל מטרה מומצאת.
3. הרץ `npm.cmd run qa:coverage-manifest` ובדוק את הפרשי המניפסט.
