עודכן: 26.08.2026 — §66, מחיקת דייר נעצרת על שומרי החסינות.

הקובץ מכיל רק חוב פעיל. סעיפים שנסגרו, תכניות קמפיין וראיות היסטוריות נשמרים ב־Git history.
שאלה עסקית יושבת ב־`OPEN-DECISIONS.md`; כאן מתועדת רק המגבלה, הראיה והצעד הבא.

לפני סגירת סעיף יש להוסיף או לעדכן טענה בשער. הצלחה היסטורית או קריאת קוד לבדה אינן PASS.

- **ראיה:** `0057_scope_enforcement.sql`, ‏`0095_scope_enforcement_marker_hardening.sql`,

### §10 — `p2_invoice_without_order_count()` רגיש ל־RLS

- **מצב:** הפונקציה היא invoker ומשתמשת ב־`NOT EXISTS` על קישור שמסונן ב־RLS. הקוראים החיים
  מוגבלים ל־owner/office בלקוח, אך החוזה אינו נאכף בגוף ה־RPC.
- **סיכון:** קורא עתידי מתפקיד אחר עלול לקבל מספר שגוי, לא דליפת שורות.
- **ראיה:** `p2_data_reliability.sql`, ‏`src/lib/alerts.ts`,
  `src/pages/serverListScreens.spec.tsx`.
- **הצעד הבא:** הכרעה בין guard תפקיד בשרת לבין `SECURITY DEFINER` עם scope מפורש.
- **עדכון 20.08.2026 — "הקוראים החיים מוגבלים ל-owner/office" אינו נכון יותר, והמדידה גם מצמצמת
  את הסיכון.** העוזר (`supabase/functions/assistant/tools/open-alerts.ts`) קורא את הפונקציה, ובכך
  מרחיב את קבוצת הקוראים החיים — בדיוק מה שהסעיף הזה חזה. **אבל** נמדד ששלושת התפקידים הפעילים
  מקבלים את אותו מספר: הפונקציה היא invoker ומסוננת לארגון (`0137:2320-2337`), ומדיניות
  ‏`iol_select` (`0022:251-252`) פורשת על owner/office/kitchen/accountant — ולכן ה-`NOT EXISTS`
  רואה את אותם קישורים עבור כל שלושתם. אין ניצול, ואין מספר שגוי היום. מה שנשאר פתוח הוא הטענה
  עצמה: הסעיף מצדיק את קיומו בכך שהקוראים מוגבלים בלקוח, וזה חדל להיות המצב. יש להכריע — לאכוף
  את החוזה בגוף ה-RPC, או לנסח מחדש את הסעיף סביב מה שנמדד.

**נמדד 19.08.2026 (ליקוי 12ב) — הכותב הוא החסם, לא שומר הטוקנים.** הבקשה לצבוע את חוברת הרו״ח
בצבעי המותג נבדקה ישירות מול ה־`xlsx@0.20.3` הנעוץ בריפו: תא שנשא
`{ fill: { patternType: 'solid', fgColor: { rgb: '1F4E5F' } }, font: { color: { rgb: 'FFFFFF' } } }`
עבר `XLSX.write(…, { cellStyles: true })` ואז `XLSX.read` וחזר כ־`{"patternType":"none"}`.
‏SheetJS CE מוחק מילוי וגופן של תא בכתיבה, בשקט ובלי שגיאה. באותה מדידה **שרדו** `!cols`,

`xl/worksheets/sheetN.xml` — רשומת אחת מסמנת את כל הגיליונות.

מכאן ש־`scripts/check-design-tokens.ts` **אינו** החסם: `src/lib/loginAurora.ts:38-56` מדגים מסלול
חוקי — לצייר טוקן `@theme` ל־canvas ולקרוא ממנו בתי sRGB, כך שאף ליטרל hex אינו נכתב בקוד מקור.
החסם הוא הכותב עצמו. לכן צבעי מותג בחוברת **לא מומשו ולא נוספה תלות**; במקום זאת נעשה מה שנמדד
כשורד: ‏RTL בשלושת הבנאים (כולל חוברת ה־snapshot הנעולה, שנשלחה עד כה שמאל־לימין לרו״ח עברי),
בלוק כותרת ממוזג ורוחבי עמודות ופורמט כסף גם בחוברת הנעולה.

**שתי הדרכים החוצה, ורק הן:** (א) כותב שיודע לכתוב סגנון — רישיון SheetJS Pro או ספרייה אחרת;

ולא הוכח שנשבר. השערה שנבדקה ונדחתה: שתי התראות מתחרות (הערת הכפילות מגיעה אסינכרונית ונושאת גם
היא `role="alert"`). התיקון לפי ההשערה הזו לא שינה את התדירות, ולכן היא אינה השורש.

**הצעד הבא, מדויק יותר מקודמו:** למדוד עשר הרצות רצופות **על מכונה שקטה** (בלי build, בלי דפדפן,
בלי סוכן אחר), ואם הכשל חוזר — לתקוף את הרכיב ולא את הבדיקה: לברר האם מסלול האימות של המחיר יכול
לסיים בלי להציג הודעה כלל כשה־`await` של בדיקת הכפילות מקדים אותו.

**עדכון באותו יום — השערה שלישית נבדקה ונדחתה, וההסלמה נעצרה כאן.** נמצא ש-`save()` מאמת לפי
סדר — שם, ואז **ספק**, ואז מחיר — ועוצר בכשל הראשון. אם בחירת הספק טרם הגיעה ל-state כשהלחיצה
נוחתת, הרכיב מדווח **נכון** `יש לבחור ספק`, והבדיקה שעוסקת במחיר ממתינה להודעה שהיא עצמה מנעה.
ההסבר תואם את כל הסימנים (תלות בעומס, "הרצה חוזרת מתקנת"), ולכן נוספה המתנה לתנאי המקדים —
ערך ה-select וערך שדה המחיר — לפני הלחיצה. **התדירות נשארה 1 מתוך 10.**

**20.08.2026 — מדידה שמצמצמת את השורש לשדה אחד, ומסבירה למה התיקון הקודם לא הזיז את התדירות.**

### §66 — מחיקת דייר נעצרת על שומרי החסינות: הפורקן המשותף אינו עובד לדייר שהשתמש במוצר

  התכנונית ברורה: הפורקן מספק שומרים **בשם**, בלי להחליש אותם. מי שלא קיבל את החלון פשוט לא נכלל

- **היקף מדוד:** ‏**33 פונקציות שומר** נושאות `raise exception`, יורות על `BEFORE DELETE` בטבלה עם
  `org_id`, ואין בגוף שלהן חלון purge ולא אחד משני ה־GUC שהפורקן מספק. שלוש מהן זוהו פרטנית

  עמודות שאינם מסרבים ל־DELETE. השאילתה שמייצרת את הרשימה (ניתנת להרצה חוזרת):

  ```sql
  with del_trig as (
    select distinct p.oid, n.nspname||'.'||p.proname as fn
    from pg_trigger t
    join pg_class c on c.oid = t.tgrelid
    join pg_namespace ns on ns.oid = c.relnamespace
    join pg_proc p on p.oid = t.tgfoid
    join pg_namespace n on n.oid = p.pronamespace
    join pg_attribute a on a.attrelid = c.oid and a.attname = 'org_id'
                       and a.attnum > 0 and not a.attisdropped
    where not t.tgisinternal and ns.nspname in ('public','private')
      and (t.tgtype & 8) > 0 and (t.tgtype & 2) > 0
  )
  select fn from del_trig
  where position('organization_teardown' in pg_get_functiondef(oid)) = 0
    and position('raise exception' in pg_get_functiondef(oid)) > 0
    and position('p1_financial_writer' in pg_get_functiondef(oid)) = 0
    and position('organization_lifecycle_writer' in pg_get_functiondef(oid)) = 0
  order by 1;
  ```
