THE FIX
-------
inFlightRef answers "is a request in flight". It is cleared the instant a run settles, and the
panel re-checks its guard only AFTER two awaits (list conversations, then load the newest). A
question asked and settled inside that window passed the check and was overwritten.

The missing condition is "has this panel session produced a question at all". That is askedRef:
set synchronously in submit() beside setSubmittedQuestion, never unset when a run settles, and
cleared only when the authorization fingerprint changes — a new authorization is a new person.

restoreHistory has two callers with opposite rights, so the guard could not simply be added to it:
  - the person pressing a stored conversation in the list ASKED for that thread and may replace
    what is on screen. That path keeps restoreHistory unchanged.
  - the panel offering the newest conversation on open asked nobody. That path now calls the new
    adoptHistory, which refuses once askedRef is set and otherwise delegates.
Putting the condition on restoreHistory itself would have silently broken the explicit list.

RESULT
------
All three tests pass. The third one is the guard against over-fixing: an untouched panel still
adopts the newest conversation, so the change refuses rather than disables.
