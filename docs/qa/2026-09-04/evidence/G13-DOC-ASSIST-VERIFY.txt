FINDINGS — ORACLES THAT DO NOT (FULLY) ASSERT THEIR FINDING

F1  DOC-07 · `src/lib/fileNameIsolation.spec.ts` IS BLIND TO A WHOLE CLASS OF RENDER SITE, AND
    THERE IS A LIVE UNISOLATED FILE NAME BEHIND THE BLIND SPOT — ON THE ROW'S OWN SCREEN.
    HIGHEST-VALUE ITEM IN THIS REPORT. Reported, not repaired.

    The scan's site detector is
        const READS_A_FILE_NAME = /\.(file_name|fileName)\b/;
    It requires a DOT. A component that DESTRUCTURES the prop — `function C({ fileName })` — and
    renders `{fileName}` matches nothing, so the scan never looks at it. Measured, not argued:
    reverting `DocumentScanPreview.tsx:197` from `<bdi dir="ltr">{fileName}</bdi>` back to
    `<bdi>{fileName}</bdi>` left the oracle GREEN. That site is one of the "25 file-name render
    sites in 14 files" the row says it proved. It is unguarded.

    The consequence is not hypothetical. The scan's own exemption list carries
        { needle: 'fileName={', why: 'a prop handed to a component, which isolates at its own
                                      render site' }
    — a promise about a site the regex cannot read. `DocumentReviewWorkspace.tsx:193` passes
    `fileName={snapshot.document.file_name}` into `DocumentSourceViewer`, and that component's
    header, on the CURRENT FIXED TREE, is

        src/components/document-review/DocumentSourceViewer.tsx:65
        <p className="mt-1 break-words text-sm text-ink-muted">{fileName}</p>

    No `<bdi>`, no `dir="ltr"`, no `ltrIsolate()` — no isolation of any kind. The route is
    /documents/:documentId/review (App.tsx:403 -> DocumentReview.tsx:265/290 ->
    DocumentReviewWorkspace.tsx:192), which is the screen DOC-07's row names as "the review screen
    … included". So the row's claim that every file-name render site carries the explicit LTR
    isolate is NOT true on the tree today, and the guard written to make that claim checkable
    cannot see the counter-example. A Hebrew-mixed name here will render exactly the way the row's
    own header describes: extension torn off and parked at the far margin.

    Suggested repair for whoever owns it (NOT done here — a verifier who edits stops being one):
    widen the detector to catch a bare `fileName` identifier inside JSX, or drop the `fileName={`
    exemption and require the isolate at the hand-off, so the promise is enforced where it is made.
