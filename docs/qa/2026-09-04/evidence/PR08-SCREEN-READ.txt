PR 08 — /pay read at 1440x900, system Edge through playwright-core, reducedMotion: reduce,
deviceScaleFactor 2. Five images, all read, RED against GREEN.

HOW THESE WERE RENDERED, and what that does and does not prove.
The shared local Supabase stack is at migration head 0245 against a 0314 tree and another agent
holds it, so nothing here was rendered against a database. A Vite dev server was started on port
5344 (not 5199, which belongs to the project and possibly to another agent) with its own cacheDir
under .tmp — node_modules in this worktree is a JUNCTION to the shared checkout, so the default
node_modules/.vite would be shared with every other agent's harness on this machine.
VITE_SUPABASE_URL points at 127.0.0.1:59998, where nothing listens, and every /rest/v1 call was
answered by a Playwright route handler from fixtures written by hand; `missedRoutes` came back
empty on all four runs, so no read reached past the harness. These images prove what the COMPONENT
draws for a given server answer. They do not prove what the server answers — that is the server
half of ruling #353 and it is PR 9.

The RED pair was produced by restoring the three product files to their HEAD content, rendering,
and putting them back. No git state was changed to do it: `git stash` and `git checkout` in a
campaign where several agents share one object store is how a verified commit gets lost.

The same dialog with data-theme="dark" (--color-canvas resolves to oklch(13% 0.028 209), so the
theme really applied — a screenshot of a page that failed to switch would be the light one again).
All three notes keep their tone separation and stay legible: the exception block deep maroon on
near-black, the settled block amber-on-brown, the bank-details block blue. The `פתיחת החריג` link
is underlined and inherits the alert foreground rather than a link colour of its own.

Shot because this screen gains three coloured surfaces with this change and the product has had a
dark-theme contrast defect before (PR 21, RTL-A11Y-06). No new colour PAIR is introduced — every
class here (`note-alert`/`note-await`/`note-info`, `badge-alert`/`badge-await`, `text-ink-body`,
`text-ink-muted`, `num`) already exists in the token layer and in the contrast manifest, which is
why `check:tokens` and `check:appearance-scope` pass untouched.
