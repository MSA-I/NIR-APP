HOW THESE WERE RENDERED, and what that does and does not prove.
The shared local Supabase stack is at migration head 0245 against a 0314 tree and this agent was
told not to touch it, so nothing here was rendered against a database. A Vite dev server was
started on port 5311 (not 5199, which belongs to the project and possibly to another agent) with
VITE_SUPABASE_URL pointed at an origin nothing listens on, and every /rest/v1 and /auth/v1 call
was answered by a Playwright route handler from fixtures written by hand. So these images prove
what the COMPONENTS draw for a given server answer. They do not prove what the server answers —
that is what the migrations quoted in the ledger rows are for, and no row here claims otherwise.

Two things the harness had to get right before anything rendered at all, recorded because the next
agent will hit them: PostgREST answers .single()/.maybeSingle() with an OBJECT rather than a
one-element array, and a cross-origin fulfil must send access-control-expose-headers:
content-range or postgrest reads no count and every server-mode list refuses to state a total.
