## 1. Executive Summary

**המצב.** שכבת הטוקנים של המוצר בוגרת ואכיפה. הסריקה מצאה **0** ליטרלי hex, **0** ‏`rgba()`,
**0** מחלקות פלטה גולמיות ו-**0** ‏`inline color` בכל 140 קובצי ה-`tsx`. היררכיית הטקסט מלאה
(שבע מדרגות + היפוך + סטטוס), רמפת המותג מאוחדת (‏8 טוקני `action` + ‏`focus`), ומטריצת ניגודיות
מלאה קיימת ומתוחזקת ב-`DESIGN.md:915-945`. ‏PR #78 סגר את הדליפות שהיו **מתחת** לשכבת הטוקנים —
צללים שהעתיקו ידנית `rgb()`, ‏glow שאיית מחדש את ליטרל המותג, ו-`text-white` ב-23 מקומות.

**מה שנשאר פתוח.** שלוש בעיות מבניות, כולן נמדדו בקוד ואף אחת אינה תיאורטית:

1. **סולם ההגבהה אינו מטוקן בקצה העליון.** למוצר חמישה טוקני `--shadow-*`, אבל שלושת המשטחים
   הגבוהים ביותר — מודאל, טוסט ופקד צף — עוקפים אותם ומשתמשים ב-`shadow-xl`/`shadow-lg`/`shadow-sm`
   של Tailwind מהמדף. ‏`check:tokens` אינו תופס זאת מפני שהוא סורק **צבעים**, לא הגבהה.
2. **אין שכבת נתונים סמנטית.** ‏`LineSeries.color` הוא מחרוזת גולמית שכל אתר קריאה בוחר בעצמו,
   ושני גרפי ההשוואה הקיימים כבר סוטים זה מזה בצורה הגרועה ביותר האפשרית: הדשבורד **הראשי**
   מפריד בין שתי סדרותיו ב-**1.56:1** ונשען כולו על מקף, ודשבורד רו"ח מפריד ב-**4.23:1**
   ו**מוותר** על המקף. אין הגדרה משותפת ל"סדרה א' מול סדרה ב'", ואף שער לא מדד מעולם צבע
   גרף מול **הצבע שלצידו** — רק מול המשטח.
3. **‏`--color-section-*` הם שלושה שמות לערך אחד** — בדיוק האנטי-דפוס שהפרומפט אוסר בסעיף 1.
   מתועד כחוב מכוון, אך עדיין לא הוכרע.

**היעד.** לא רמפה חדשה ולא פלטה חדשה. שלוש סגירות ממוקדות: **שני** טוקני צל חדשים, **חוזה תפקידי-סדרה
אחד** ב-`theme.ts` (ללא טוקני CSS חדשים כלל), והכרעת בעלים אחת על `section-*`. סך התוספת המוצעת
לשכבת ה-CSS: **שני טוקנים**. הפרומפט דורש שלכל טוקן תהיה סיבה ברורה להתקיים; שלושה מהם כאן אין.

## 2. Current-State Audit — הטוקנים שקיימים בפועל

### 2.1 שכבת ה-primitives

המוצר **אינו** מגדיר פלטה ראשונית משלו. ה-primitives הם:
- **‏oklch מפורש** לכל טוקן מבני (קנבס, משטחים, קווים, דיו, מותג, רמפת גרפים).
- **רמפות Tailwind מהמדף** (`--color-emerald-*`, `--color-amber-*`, `--color-rose-*`,
  `--color-sky-*`, `--color-slate-*`) לכל משפחות הסטטוס ולכוכבי הדירוג.

זו החלטה תקפה מול מודל התלות שהפרומפט מגדיר — רמפת Tailwind היא שכבת primitive לגיטימית — אך
היא **לא מתועדת ככזו**. אין ב-`DESIGN.md` משפט שאומר "שכבת ה-primitive שלנו היא oklch למבנה
ו-Tailwind לסטטוס". זה פער תיעוד, לא פער קוד.

### P1 — סולם ההגבהה נשבר בדיוק במדרגה העליונה · **High**

**קובץ:** `src/components/ui.tsx:778` · `src/components/ui.tsx:853` ·
`src/components/document-review/DocumentScanPreview.tsx:98`

**המימוש הנוכחי:**
```tsx
// ui.tsx:778 — פאנל המודאל
className={`dialog-panel-safe bg-surface rounded-t-2xl sm:rounded-2xl shadow-xl w-full …`}
// ui.tsx:853 — הטוסט
className={`rounded-lg px-4 py-2.5 text-sm text-on-solid shadow-lg …`}
```

**למה זו בעיה.** למוצר חמישה טוקני צל שכולם נגזרים מ-`--color-shell`/`--color-action` דרך
`color-mix`, כדי שרה-תמה של המותג תזיז גם את האטמוספרה. ‏`shadow-xl` של Tailwind הוא
`rgb(0 0 0 / 0.1)` שחור ניטרלי — **הוא לא ייצבע מחדש לעולם**. זו בדיוק הדליפה ש-PR #78 סגר
בטוקני הצל, שנותרה פתוחה בשלושת המשטחים החשופים ביותר: המודאל הוא המשטח הגבוה ביותר בכל המוצר,
והטוסט הוא ההודעה היחידה שצפה מעל הכול.

בנוסף: המודאל יושב על `bg-surface` — **אותו ערך כמו כרטיס רגיל**. ההפרדה בין "כרטיס" ל"דיאלוג
מודאלי" נשענת כולה על צל שאינו בשליטת מערכת הטוקנים.

**חומרה: High.** לא באג חזותי היום, אבל הוא שובר את החוזה המרכזי של הארכיטקטורה ("רה-תמה =
שלושה קבצים") בדיוק במקום שהמשתמש מסתכל בו כשהוא מאשר תשלום.

### P2 — אין חוזה לתפקידי סדרה בגרפים · **High**

**קובץ:** `src/components/charts.tsx:344` · `src/pages/Dashboard.tsx:918` ·
`src/pages/dashboards/AccountantDashboard.tsx:157`

**המימוש הנוכחי:**
```ts
// charts.tsx:344 — הצבע הוא מחרוזת חופשית שהקורא בוחר
export type LineSeries = { key: string; name: string; color: string; dash?: boolean };
```
```tsx
// Dashboard.tsx:918 — רכש מול תשלומים
series={[{ key: 'purchases', name: 'רכש',      color: t.bars[0] },
         { key: 'payments',  name: 'תשלומים', color: t.bars[3], dash: true }]}

// AccountantDashboard.tsx:157 — תשלומים מול חיובי בנק

         { key: 'bank',     name: 'חיובי בנק', color: t.bars[2] }]}
```

**למה זו בעיה.** שני גרפי השוואה, שתי מוסכמות שונות — ו**הן נבדלות ביחס של פי-2.7 בהפרדה
הנמדדת בין שתי הסדרות**:

| מסך | הזיווג | ניגודיות בין הסדרות | מקף |
|---|---|---|---|
| `Dashboard` (רכש / תשלומים) | `chart-1` + `chart-4` | **1.56:1** | כן |
| דשבורד רו"ח (תשלומים / בנק) | `chart-1` + `chart-3` | **4.23:1** | **לא** |

(המספרים חושבו מחדש מהערכים ב-`@theme`; הם תואמים את הפנקס ב-`PROGRESS.md`.)

הצירוף הגרוע ביותר האפשרי: המסך שהזיווג שלו **חלש** הוא זה שנושא מקף, והמסך שהזיווג שלו **חזק**
הוא זה שוויתר עליו. במסך הראשי שני הקווים הם 1.56:1 זה מול זה — "שני הכהים של המערכת", לפי
ההערה ב-`Dashboard.tsx:915`, שנבדלים **אך ורק** במקף. ברגע שהמקף אובד — הדפסה בגווני אפור,
צילום מסך דחוס, מסך זול, או משתמש שמסתכל מזווית — שני הקווים מתמזגים לאחד.

- ‏`DESIGN.md:321` קובע ש"סדרה רביעית ומעלה חייבת `dash`/marker". שני הגרפים דו-סדרתיים, כלומר
  שניהם "עומדים בכלל" — והכלל אינו אומר דבר על כך שהאחד מפריד ב-1.56 והשני ב-4.23.
- ‏`color: string` מקבל כל מחרוזת. גרף שלישי יכול לבחור `bars[1]+bars[2]` — **1.89:1** — ואף
  שער לא יעצור אותו. ‏`check:tokens` בודק שאין ליטרל צבע; הוא אינו יכול לבדוק ש**המדרגה שנבחרה
  מובחנת מזו שלצידה**.

זהו בדיוק מה שסעיף 4 בפרומפט מבקש: *"design a **separate semantic data-visualization layer**"*,
במקום להסתמך על צבעי ממשק רגילים.

**חומרה: High.** הסטייה כבר קרתה בפועל בין שני מסכים חיים, וללא חוזה היא תחזור בכל גרף חדש.

### P3 — `--color-section-*`: שלושה שמות, ערך אחד · **Medium**

**קובץ:** `src/index.css:112-114`

**למה זו בעיה.** הפרומפט מגדיר במפורש בסעיף 1: *"the final architecture should prevent `muted`,

לתחום הכספים. ההבטחה אינה מקוימת.

**חומרה: Medium.** אפס השפעה חזותית. ההשפעה היא על מפתח שיקרא את השם ויסיק ממנו יכולת שאינה קיימת.

"‏placeholders and hints — AA on canvas", והוא כוונן לפי קריאוּת של אותיות. הוא מוגש כאן
כ-**stroke של קו גרף** ב-`PriceSparkline` (`supplier-metrics.tsx:151`) וב-`PriceLists.tsx:279`
כשמחיר לא השתנה.

התוצאה: כוונון עתידי של `ink-faint` מסיבת קריאוּת של טקסט יזיז קו בגרף, וכוונון מסיבת גרף
ישבור placeholder. שתי סיבות שינוי מנוגדות על טוקן אחד — הפרה של מודל התלות שהפרומפט מגדיר.

**חומרה: Medium.** ‏latent. אין באג היום.

## 4. Proposed Color Architecture

**עיקרון מנחה לתוכנית הזו: התוספת המינימלית שסוגרת את הפער הנמדד.** הפרומפט דורש
*"every token must have a clear reason to exist"* ו-*"prefer the smallest token architecture"*.
לכן שתיים משלוש הסגירות המוצעות **אינן מוסיפות אף טוקן CSS**.

### 4.1 Primitives — ללא שינוי, עם תיעוד

שכבת ה-primitive נשארת כפי שהיא (oklch למבנה, רמפות Tailwind לסטטוס). מתווסף **משפט אחד**
ב-`DESIGN.md` שמצהיר על כך במפורש, כדי שמודל התלות יהיה קריא ולא משתמע.

### 4.2 משטחים — **לא** מוסיפים מדרגה שישית

הפרומפט מבקש מדרגת `Elevated`. **ההמלצה: לא להוסיף טוקן צבע.**

הנימוק נמדד: הכרטיס עומד על `oklch(99.2%)`. מדרגה "מוגבהת" מעליו הייתה חייבת להיות בהירה
מ-99.2% — כלומר לבן טהור, הפרש של 0.8 נקודות בהירות. **זה בלתי-נראה על נייר.** במערכת כהה
(שהפרומפט הניח) מדרגה מוגבהת עובדת מצוין; במערכת בהירה היא לא קיימת פיזית.

**במקום זה: ההגבהה נשארת צל, והצל נסגר כטוקן.** זה מתקן את הפגם האמיתי (‏P1) בלי טוקן צבע שקרי.

### 4.3 הגבהה — שני טוקנים חדשים

```css
/* דיאלוג מודאלי — המשטח הגבוה ביותר במוצר. מחליף את shadow-xl מהמדף. */
--shadow-dialog:
  0 4px 10px  color-mix(in oklab, var(--color-shell) 10%, transparent),
  0 24px 48px -12px color-mix(in oklab, var(--color-shell) 22%, transparent);

/* טוסט — צף מעל הכול, קצר-חיים, ולכן קשה יותר מהמודאל ולא רך יותר. */
--shadow-toast:
  0 2px 6px   color-mix(in oklab, var(--color-shell) 12%, transparent),
  0 12px 24px -8px color-mix(in oklab, var(--color-shell) 24%, transparent);
```

ידית הפינה ב-`DocumentScanPreview` אינה מצדיקה טוקן שלישי — היא מקבלת `--shadow-card`.

**סולם ההגבהה המלא אחרי השינוי:** `card` → `card-hover` → `dashboard` → `menu` → `toast` →
`dialog` → `fab`. שבע מדרגות, כולן נגזרות מ-`shell`/`action`, אפס ברירות מחדל של Tailwind.

### 4.4 טקסט — ללא שינוי

שבע המדרגות עומדות בכל דרישות הפרומפט. אין מה להוסיף ואין מה למחוק.

### 4.5 מותג — ללא שינוי

הפרומפט מונה `primary-active`. הבדיקה מצאה שלחיצה משתמשת ב-`surface-selected` **בעקביות** על
פני כל הפקדים (`ui.tsx:377`, `463`, `570`). זהו מנגנון אחד, נכון, ומתועד. טוקן `action-active`
היה מדרגה שישית למותג בלי צרכן.

### 4.6 נתונים — חוזה תפקידים, **אפס טוקני CSS חדשים**

הפער ב-P2 אינו חוסר בצבעים — יש חמישה. הפער הוא ש**אין שם לתפקיד**, ולכן אין מי שיכריע איזה
זיווג נכון. ההצעה: פונקציה אחת ב-`src/lib/theme.ts` שמחזירה את הזיווג, במקום שכל אתר קריאה
יבחר אינדקסים בעצמו.

**מטריצת הזיווגים המלאה** (חושבה מהערכים ב-`@theme`, לצורך ההכרעה):

| **chart-2** | — | 1.89 | 3.51 | 3.11 |

**‏✅ הוכרע ע"י הבעלים, 19.08.2026: חלופה א'.** ההכרעה גוברת על הסקיצה הקודמת שתועדה
ב-`Dashboard.tsx:915` ("שני הכהים, נבדלים במקף"). שתי החלופות שנשקלו:

**דבר** להבחנה, והמקף הוא נשא יחיד. ‏(א) מוסיפה נשא שני בלי לוותר על הראשון, ומעלה את שני
המסכים לאותה רמה. זה גם מה שדשבורד רו"ח כבר עושה בפועל — חסר לו רק המקף.

```ts
/** תפקידי סדרה בגרף השוואה. הזיווג נקבע כאן במדידה, לא באתר הקריאה. */
export type SeriesRole = 'primary' | 'counterpart';

  primary: { key: string; name: string },
  counterpart: { key: string; name: string },

```

**מה זה קובע, ומה זה מונע:**
- זיווג אחד לכל גרפי ההשוואה במוצר — הסטייה בין `Dashboard` ל-`AccountantDashboard` נסגרת.
- ה-`dash` על הסדרה השנייה הופך **חובה**, לא בחירה. זו ההקלה שסעיף 4 בפרומפט דורש
  ("‏do not rely exclusively on hue" — combinations of color **and line style**).
- ‏spec אחד (`colorLanguage.spec.ts`, קיים) מצמיד את הזיווג, את המקף, ואת רף ה-3:1 בין הסדרות —
  כך שזיווג עתידי מתחת לרף ייפול בשער ולא בעין.

**‏`forecast`/`projected`: N/A מתועד.** הפרומפט מבקש שכבת current/previous/**forecast**. נסרק
כל המוצר — **אין תחזית בשום מסך**. בניית טוקן לתחזית שאינה קיימת מפרה במפורש את ההנחיה
*"avoid creating an unnecessarily huge chart palette if the product does not actually require it"*.
נקודת החזרה: היום שבו יופיע מסך תחזית תזרים.

**‏P4 (`flat`):** ‏`chartTheme().flat` יעבור מ-`--color-ink-faint` ל-**`--color-chart-3`**.
ערך קרוב, שייך לשכבה הנכונה, ומשחרר את `ink-faint` לכוונון טקסט חופשי.

**‏P5 (אדום-ירוק):** ההמלצה היא **לא** להחליף גוונים. ‏`PriceSparkline` הוא 96×28 ללא צירים —
שם הצבע באמת נושא משקל, ולכן התוספת המוצעת היא **חץ-כיוון glyph** לצד הניצוץ (▲/▼), הנשא
השני שאינו צבע. גרף היסטוריית המחירים כבר נושא צירים, ‏tooltip ונקודות ואינו זקוק לשינוי.
זו תוספת של רכיב, לא של טוקן — ולכן היא **מחוץ** להיקף סגירת הצבע, ונרשמת ל-`DEBT-REGISTER`.

## 6. Contrast Matrix

**המטריצה הקיימת נשארת מקור האמת** — `DESIGN.md:915-945`. היא מכסה את כל צירופי הטקסט

**מה שהתוכנית הזו מוסיפה למדידה.** צל אינו נמדד בניגודיות — הוא אינו אובייקט מידע. שני

**ללא רגרסיה במטריצה הקיימת** — אף טוקן צבע קיים אינו משנה ערך בתוכנית הזו.

## 12. Final Proposed Token Specification

הסט המלא שסוכן מימוש יכול ליישם ישירות. **כל השאר ב-`@theme` נשאר בדיוק כפי שהוא.**

```css
/* ---- הגבהה: השלמת הסולם. שני טוקנים חדשים, שניהם נגזרים כמו החמישה הקיימים ---- */

/* דיאלוג מודאלי — המשטח הגבוה ביותר במוצר. מחליף shadow-xl של Tailwind, שהוא שחור
   ניטרלי ולכן היה שורד רה-תמה של המותג בלי להשתנות. */
--shadow-dialog:
  0 4px 10px color-mix(in oklab, var(--color-shell) 10%, transparent),
  0 24px 48px -12px color-mix(in oklab, var(--color-shell) 22%, transparent);

/* טוסט — צף מעל הכול וקצר-חיים, ולכן קשה מהמודאל ולא רך ממנו. מחליף shadow-lg. */
--shadow-toast:
  0 2px 6px color-mix(in oklab, var(--color-shell) 12%, transparent),
  0 12px 24px -8px color-mix(in oklab, var(--color-shell) 24%, transparent);

/* ---- זהות מרחב: 3 טוקנים בערך אחד → טוקן אחד (מותנה בהכרעת בעלים) ---- */

/* שם אחד לטיפול אחד. T7.3 הכריע שהגוונים הנפרדים אינם חוזרים; שלושה שמות לערך זהה
   הבטיחו הבחנה שאינה קיימת. אם הבחנת-גוון תשוב — זו נקודת ההרחבה, ומכאן 3 ליטרלים + spec. */
--color-section-accent: oklch(33.66% 0.058 209);
```

```ts
/* ---- src/lib/theme.ts — חוזה תפקידי סדרה. אפס טוקני CSS חדשים ---- */

/** גרף השוואה נושא שני תפקידים בלבד, וזיווגם נקבע כאן ולא באתר הקריאה.
 *  primary     = chart-1, המדד שהמסך עוסק בו.
 *  counterpart = chart-3 מקווקו, הצד השני.
 *  נמדד: chart-1 ↔ chart-3 = 4.23:1. הרמפה מונוכרומטית, ולכן ההפרדה היא בהירות —
 *  והמקף אינו קישוט אלא הנשא השני שאינו צבע. הוא חובה, לא אפשרות.
 *  הזיווג שהוחלף (chart-1 + chart-4) מדד 1.56:1 והשעין את כל ההבחנה על המקף לבדו. */
export function comparisonSeries(
  primary: { key: string; name: string },
  counterpart: { key: string; name: string },
): LineSeries[] {
  const t = chartTheme();
  return [
    { ...primary, color: t.bars[0] },
    { ...counterpart, color: t.bars[2], dash: true },
  ];
}

/** flat עבר מ---color-ink-faint ל---color-chart-3: קו בגרף שייך לשכבת הנתונים,
 *  ו-ink-faint מכוונן לקריאוּת של placeholder. שתי סיבות שינוי, שני טוקנים. */
```

**סיכום התוספת:** ‏2 טוקני CSS חדשים · ‏1 טוקן CSS מאוחד מ-3 · ‏1 פונקציה · ‏0 גוונים חדשים ·
‏0 שינויי ערך בטוקן קיים.
