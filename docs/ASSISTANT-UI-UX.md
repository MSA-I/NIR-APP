## Job, קהל והבטחת המשטח

**Job:** לאפשר לאדם לשאול שאלה תפעולית, להבין בתוך שניות מה נמדד ומה לא, ולפתוח את מקור הראיה
בלי לאבד את השאלה או את הממצא שהוביל אליו.

**קהל:**

- `owner` — תמונת מצב, חריגים, כסף שדורש תשומת לב ובקרה;
- `office` — הזמנה, קבלה, חשבונית, מחירון וספק בתוך מסע הרכש;
- `accountant` — חשבוניות מאושרות, תשלומים, בנק, זיכויים ודיווח כספי.

**הבטחה:** תשובה היא תוצאת בדיקה מורשית, לא שיחה ולא מקור אמת חדש. כל טענה חומרית מחוברת לעובדה,
לעדכניות ולמקור נגיש כרגע. `0`, ‏`—`, ‏partial, ‏not measured ו־not permitted נשארים מצבים שונים.

## הצלחה וראיות קבלה

המשטח מצליח כאשר:

1. המשתמש מבין בלי tooltip שזהו כלי בדיקה ולא chatbot כללי.
2. השאלה שנשלחה נשארת גלויה לצד התוצאה.
3. כל ממצא מציג ניסוח, ערך, יחידה, `as_of` ומקור מורשה.
4. פתיחת מקור אינה מוחקת run, question, scroll position או נתיב חזרה.
5. `owner`, ‏`office` ו־`accountant` אינם רואים route, fallback, label או history metadata שאסורים להם.
6. סגירה בזמן pending ופתיחה מחדש ממשיכות אותה ריצה בלי שליחה כפולה.
7. 390, ‏768, ‏1023 ו־1440 פיקסלים נשארים ללא overflow, עם יעדי מגע של 44px לפחות.
8. שם נגיש, סדר כותרות, focus, ‏Escape, ‏Tab/Shift+Tab ו־reduced motion נבדקים בדפדפן אמיתי.

ראיית design approval חייבת לכלול אותן שאלה ותשובה ארוכה בשתי החלופות ובכל ארבעת הרוחבים,
צילום של פתיחת מקור, trace מקלדת ובדיקת DOM/נגישות. צילום לבדו אינו סוגר את השער.

  > עומדים בעינם. **מה שלא השתנה ואינו נתון לוויתור:** התשובה נשארת **כרטיס ראיות ולא פרוזה** —
  > לכל ממצא ערך, עדכניות ומקור. בועה היא צורת הצגה; היא אינה רישיון לענות בלי ראיה.

- אין שינוי shell, dashboard, route machine identifiers או design system כחלק מהכרעת המשטח.
