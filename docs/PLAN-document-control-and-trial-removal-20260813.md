## חוזי נתונים

- `organization_access_state()` שומר על שמו וצורתו, אך מחזיר רק `active`, `offboarding` או `suspended`; שדות Trial/Grace תמיד `null` וכתיבה מותרת רק ב־`active`.
- `get_document_operations_metrics(integer)` שומר על שמו אך מחזיר מדדים תפעוליים בלבד.
- read-model חדש לניסיונות עיבוד חושף רק מזהי פעולה/ניווט, סטטוס, זמנים, מספר ניסיונות וסיבת תקלה שניתנת למיפוי אנושי.
- read-model חדש לתור מחירונים חושף רק מסמך, מוצר, מחיר והתקדמות הנדרשים להחלטה אנושית.
- RPC-ים של calibration metrics, drift וניסיונות עיבוד טכניים אינם נשארים נגישים לדפדפן לאחר שהמסך עבר לחוזים הבטוחים.

## שערים ומגבלת לולאה

- כל תוצאה נרשמת ב־ledger עם: `gate`,‏ `coverage`,‏ `sha`,‏ `started_at`,‏ `finished_at`,‏ `result`,‏ `artifact` ו־`failure_fingerprint`.
- PASS תקף לאותו SHA. בדיקה ממוקדת נשמרת כשהשינוי המאוחר אינו נוגע בתחום הכיסוי שלה.
- אחרי כשל מריצים תחילה רק את הבדיקה הממוקדת שנכשלה. לכל fingerprint מותרים שני תיקונים ממוקדים; הישנות שלישית היא `BLOCKED`.
- `npm.cmd run build` מורץ פעם אחת אחרי הקפאת ה־diff; אם הוא נכשל, מתקנים רק את הגורם ומריצים מחדש כדי להשיג PASS. אין `npm run quality` מקומי.
- בפריסה לא חוזרים על build או quality ירוקים של SHA השחרור. SHA חדש שנוצר במיזוג מקבל את ריצת ה־CI האוטומטית היחידה שלו.
