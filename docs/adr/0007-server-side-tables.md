# ADR 0007 — TanStack Table בתוך `DataTable`, ושליפה בצד שרת

**סטטוס:** מאומץ · **תאריך:** 2026-08-04

## הקשר

`DataTable` (`ui.tsx:574-762`) עובד היום כולו בצד לקוח: חיפוש רק אם ה-caller מעביר `searchFn`, מיון
רק עם `Column.sortValue` ובעמודה אחת, עימוד `slice`, ללא בורר גודל-דף וללא וירטואליזציה.

**הבעיה החמורה יותר אינה בטבלה — היא בשליפה.** כל מסך רשימה טוען את **הטבלה כולה** ללקוח דרך
`fetchAll` (`supabasePaging.ts:7`), שמלפף `.range()` בדפים של 1000 עד שנגמר, ורק אז מסנן בזיכרון
(`Invoices.tsx:64-68`, `DocumentsInbox.tsx:293-296`). ב-`DocumentsInbox.tsx:333-334` כבר רשום TODO
מפורש להעביר את הסינון לשרת.

בנוסף, **10 טבלאות עוקפות את `DataTable` לגמרי**, ורק ל-2 מהן יש נפילה למובייל.

## ההחלטה

1. **‏`@tanstack/react-table` נכנס *בתוך* `DataTable`.** חוזה ה-props הקיים נשמר בית-בית עבור כל
   הקוראים הנוכחיים; כל היכולת הארגונית היא props חדשים באופט-אין. **הרכיב אינו מוחלף.**
2. **ענף כרטיסי המובייל (`ui.tsx:631-689`) נשמר כפי שהוא.** המובייל אינו הופך לרשת דסקטופ דחוסה —
   זו דרישה מפורשת בבריף וגם החלטה קיימת ב-`DESIGN.md:211-217`.
3. **שליפה בצד שרת מחליפה את `fetchAll` במסכים בעלי נפח.** ‏`fetchAll` נשאר בשימוש היכן שהוא נכון —
   ייצוא מלא, למשל, שבו הכוונה *היא* לקבל הכול.
4. **וירטואליזציה רק היכן שנמדד צורך**, לא כברירת מחדל.

## תוצאות

- **"תצוגות שמורות" אינן חלק מהגל הזה.** הבריף מסקף אותן לפי `optional branch` ודורש audit לשינוי
  בתצוגה משותפת — כלומר הן אינן ניתנות לבנייה נכונה לפני שהסניף קיים. הן נדחות לגל ההיררכיה. עד אז
  העדפות עמודה ב-`localStorage`, **מתועד כזמני** ולא מוצג כתכונה ארגונית (`OPEN-DECISIONS.md` #80).
- **משמעת ה-null נשמרת.** ספירות בצד שרת חייבות להמשיך לכבד את `readExactCount` (`queryResult.ts`) —
  ספירה שאינה זמינה **זורקת** ולעולם אינה מוצגת כאפס.
- **באג קיים נסגר בדרך:** `useEffect(() => setPage(0), [q, rows.length])` (`ui.tsx:612`) **אינו** מאפס
  עמוד בשינוי מיון, כך שמיון בעמוד 4 מציג את השורות הלא-נכונות.
- **שלוש נקודות השבירה מאוחדות.** היום `lg` למעטפת, `md` לכרטיסי `DataTable`, `xl` ל-`Reports`
  ולפיצול מסך הסקירה — כל רכיב מצהיר `matchMedia` משלו.
- הפילטרים ממשיכים לחיות ב-slot ה-`toolbar` הקיים ולהיות מסונכרנים ל-URL דרך `useParamState.ts`.

## חלופות שנדחו

**להחליף את `DataTable` ברכיב טבלה מוכן** — מוחק את ענף כרטיסי המובייל, את מודל ה-`priority`
ו-`mobileLabel`, ואת ה-`aria-sort` עם כפתורי מיון אמיתיים. הבריף אוסר להסיר את ערכת ה-UI הקיימת אלא
אם רכיב הוכח כלא-בטוח.
**להשאיר את הכול בצד לקוח ולהוסיף רק וירטואליזציה** — מקצר את זמן הרינדור ולא את השליפה. מסך שמוריד
50,000 שורות נשאר איטי, ו-PostgREST ממשיך להחזיר את כולן.
**להעביר לשרת רק את העימוד** — סינון ומיון בצד לקוח על דף אחד נותן תשובות שגויות: "המיון" ממיין את
הדף, לא את התוצאה.
