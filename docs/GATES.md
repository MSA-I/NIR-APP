# GATES — acceptance ledger for the 2026-09-04 sweep

One row per finding. A wave is not finished because its pull request merged; it is finished when
every row below it reads `MET`, with the evidence named. A row given up on reads `ABANDON:`
followed by the reason — never a blank, and never a silent drop.

**Status.** `PENDING` not started · `DIAGNOSED` cause read in the tree, files named, no fix yet ·
`FIXED` change written, oracle not re-run · `MET` oracle re-run green, evidence path given ·
`BLOCKED` waiting on a named owner decision · `ABANDON:` given up, with the reason ·
**`NOT A DEFECT`** measured, and the measurement says the product is right — added 05.09.2026
because `PERM-03` and `PERM-05` were being filed as `ABANDON:` for want of a word. They are the
opposite of given up: both were measured to a verdict. Filing a completed measurement as an
abandonment is a false claim about the work, which is the thing this ledger exists to prevent.

**The oracle column is the point.** It states the condition that is FALSE before the fix and TRUE
after. Where a row's oracle is not one this plan derived, it is the acceptance criterion **the
sweeping agent itself wrote** in that finding's `expected` field — not a restatement of the
symptom. "It looks right" is not an oracle and no row may reach `MET` on one.

**Files** names what a fix touches, and is filled only where the cause was actually read in the
tree. An empty files cell beside a `PENDING` status is an honest "not diagnosed yet" — it is not
a fix waiting to be claimed.

Counted from the sweep aggregate: **146 findings · 138 actionable · 8 not defects.** Every id
appears exactly once, checked mechanically.
