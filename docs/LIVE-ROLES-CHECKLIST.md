# צ'קליסט אימות חי — שלושת התפקידים (DEBT-REGISTER §26)

> להרצה ע"י הבעלים מטלפון אמיתי (או דפדפן ברוחב ~390px), מול
> `https://supplyflow-baq.pages.dev`, אחרי פריסת קמפיין 09.08.2026.
> הסוכן אינו מחזיק סיסמאות ואינו מתחבר בשם משתמשים — לכן הצעד הזה שלך.
> לכל סעיף: צילום מסך אחד מספיק. סטייה מהמצופה = לרשום מה קרה בפועל.

## מנהל מטבח (kitchen)

1. **כניסה** → הדשבורד נטען.
2. **קבלת סחורה:** ‏תפריט → קבלת סחורה → בחר הזמנה פתוחה → סמן שורה אחת **פגום**.
   - מצופה: תיבת "פתיחת דרישות זיכוי אוטומטית לחוסרים, לפריטים פגומים ולהחזרות" מסומנת.
   - סיום קבלה → מצופה: "הקבלה נשמרה!", ובהמשך ב-`/credits` (אצל מנהל) מופיעה דרישת זיכוי על הפריט הפגום.
3. **פריט שלא הוזמן:** במסך קבלה עם תעודת משלוח שיש בה שורה לא מזוהה — מצופה משפט
   "פתיחת חריג לבירור זמינה למנהל ולמנהל הרכש בלבד" **בלי** כפתור (הכפתור מופיע רק למנהל/מנהל רכש).
4. **מצב טיסה (offline):** כבה נתונים → צלם חשבונית ממסך הקבלה → מצופה: "הצילום נשמר במכשיר
   ויועלה אוטומטית כשיחזור החיבור" → הדלק נתונים → מצופה: הצילום מופיע בתיקיית המסמכים.
5. **רענון offline:** במצב טיסה, רענן את הדף → מצופה: האפליקציה עולה (לא דף שגיאה של הדפדפן).

## מבצע העברות (payer)

1. **כניסה** → נחיתה בדשבורד; בתפריט: ‏`/pay` בלבד תחת "כספים" (בלי כותרת קבוצה מיותרת).
2. **תור התשלומים:** פתח `/pay` → דרישה עם פרטי בנק → מצופה: הפרטים מוצגים.
3. **ספק בלי פרטי בנק:** מצופה: "לא הוזנו פרטי בנק — יש לברר מול המשרד" (זה הצעד המוכרע — ‏#116
   לא נפתח ל-payer).

## ספק (supplier)

1. **כניסה** → מצופה: "המחירון שלי" בלי כותרת "רכש" מעל.
2. **הגשת מחירון:** העלה PDF לחודש הנוכחי → מצופה: ההגשה נקלטת ותוצאת הקליטה מוצגת שורה-שורה.
3. **שורה שנדחתה:** פתח "פירוט שורות שנדחו" → מצופה: ליד "המוצר אינו קיים בקטלוג" יש משפט
   למי לפנות (ולא מבוי סתום).

## לכל התפקידים

- ‏`/login` מציג "שכחתי סיסמה" + קישורי תנאי שימוש ופרטיות בתחתית.
- אחרי ההרצה: לרשום תוצאות (עבר/נכשל + צילום) ב-`docs/PROGRESS.md` ולסגור את `DEBT-REGISTER` §26.
